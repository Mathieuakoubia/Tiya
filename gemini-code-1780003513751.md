# Guide de Sécurité et d'Optimisation — Projet SOZIA
Dernière mise à jour : Mai 2026

## 1. Règles d'Optimisation & Maîtrise des Coûts Firestore

Pour éviter que l'utilisation intensive des routines en temps réel (Twin / Squad) ne provoque une explosion des coûts de requêtes (lectures/écritures), applique les principes suivants :

### A. Séparation du Temps Réel Éphémère et du Stockage Persistant
* **Règle :** Ne jamais utiliser Firestore pour stocker des états intermédiaires qui changent à la milliseconde (ex: position du doigt dans `The High-Five`, inclinaison dans `Lullaby Haptique` ou flux respiratoire en temps réel).
* **Implémentation :** Utilise l'App State local de FlutterFlow pour l'état instantané, ou passe par un canal de communication direct (WebSockets / Supabase Realtime). Firestore ne doit valider que l'état initial (`launched`) et l'état final (`completed`) de la session.

### B. Limitation Strict des Écoutes Éphémères (Streams/Queries)
* **Règle :** Ne charge jamais une collection complète. Limite au maximum la portée des `StreamBuilder` natifs de FlutterFlow.
* **Implémentation :** Filtrer systématiquement par l'identifiant unique de l'utilisateur connecté ou de sa squad (`squadId`). Utilise l'App State global pour conserver l'ID de la Squad au lieu de la re-requêter à chaque changement d'écran.

### C. Agrégation et Compteurs Atomiques
* **Règle :** Pour les routines collectives comme `Collective Shield`, ne calcule pas le niveau du bouclier en lisant l'historique complet des documents de chaque membre.
* **Implémentation :** Crée un champ entier `niveauBouclier` directement dans le document de la squad et incrémente-le de manière atomique lors de la complétion d'une routine individuelle via :
  `FieldValue.increment(1)`

## 2. Règles de Sécurité Firestore (Security Rules)

Applique ces règles d'accès strictes dans la console Firebase pour empêcher la lecture ou la modification frauduleuse des données par un client modifié (OWASP Mobile).

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Profils Utilisateurs : Lecture et écriture restreintes au propriétaire
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
    
    // Squads : Seuls les membres enregistrés dans la liste 'users' peuvent y accéder
    match /squads/{squadId} {
      allow read: if request.auth != null && request.auth.uid in resource.data.users;
      allow create: if request.auth != null;
      allow update: if request.auth != null && request.auth.uid in resource.data.users;
      allow delete: if false; 
    }
    
    // Sessions de Squad : Accès soumis à l'appartenance à la Squad parente
    match /squad_sessions/{sessionId} {
      allow create: if request.auth != null;
      allow read, update: if request.auth != null && 
        get(/$(database)/documents/squads/$(request.resource.data.squadId)).data.users.hasAny([request.auth.uid]);
    }
    
    // Invitations de Squad : Uniquement accessibles par l'émetteur ou le destinataire
    match /squad_invitations/{invitationId} {
      allow create: if request.auth != null && request.auth.uid == request.resource.data.fromUid;
      allow read, update: if request.auth != null && 
        (request.auth.uid == resource.data.fromUid || request.auth.uid == resource.data.toUid);
    }
  }
}
